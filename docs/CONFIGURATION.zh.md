# 配置

所有设置都在一页里：**设置 → 模型请求加速**。本文按值得阅读的顺序解释每一项。

**所有提供方初始都是关闭的。** 先开一个，确认它工作一天，再考虑下一个。压缩是最安全的起点；预传输则会向你的网关提出要求。

## 两个全局开关

| 设置 | 键 | 默认 | 说明 |
| --- | --- | --- | --- |
| 耗时记录 | — | — | 显示账本占用，旁边是 **清空** 按钮。清空会同时丢弃已存文档（含本进程从未载入过的会话）和运行进程持有的部分。不可撤销，行内也会写明。 |
| 显示请求耗时视图 | `timing` | `true` | 关掉它，Host 也会停止记录耗时，因此不需要这个视图的部署不为它付出任何代价。视图标签立即增删——无需刷新页面。 |

## 按提供方的设置

这些就是设置页表格对应的键。**HTTP/2 和预传输不再是表格的列**：两者都是会把投机字节提前放上链路的 beta 功能，因此只在配置文件里设置，页面在原开关的位置留一行说明。共用同一个 endpoint 的多个路由会被**分组，但各自独立配置**：每次模型调用会被归属到发出它的提供方，由该提供方自己的开关决定；只有在请求完全无法归属时才退回按 endpoint 判断。

| 列 | 键 | 默认 | 作用 |
| --- | --- | --- | --- |
| 开关 | `providers.<name>.enabled` | `false` | 是否压缩该提供方的模型请求。 |
| 算法 | `providers.<name>.encoding` | 继承 `encoding` | `brotli` 或 `gzip`。 |
| HTTP/2（**beta**，只能配置文件） | `providers.<name>.http2` | 开启预传输时默认打开 | 是否对该提供方提供 HTTP/2。见 [HTTP/2](#http2)。 |
| 预传输（**beta**，只能配置文件） | `providers.<name>.prewarm` | `false` | 是否提前把本次对话的共享历史放上线路。见 [预传输](#预传输)。 |
| 最小体积 | `providers.<name>.minBytes` | `1024` | 不在页面上，需在行的 `config` 里设置。小于它的请求原样发送；压缩后不会更小时也跳过压缩。 |

## 压缩

**它做什么：** 压缩**请求**体，并加上 `content-encoding: br`（或 `gzip`）。响应是另一回事——Node 的 `fetch` 已经自行协商并解压，本插件不参与。

**用哪种算法。** 默认 `brotli`，质量 **9**。刻意不用 brotli 自己的默认值 11：它每兆字节要花约一秒的**同步** CPU、阻塞事件循环，而收益只有几个百分点。质量 9 实测比 gzip 小约 5–15%，耗时相当。

**请求体没有协商机制**，所以插件靠试来学习。如果某个 endpoint 对 brotli body 回一个形状拒绝——`411`、`415` 或 `501`——该请求会用 gzip 重试。适配器不会看到任何它本来不会看到的失败，而该 endpoint 会被记住，因此 brotli 在那里只会被尝试一次。把**算法**设为 `gzip` 可以完全跳过这次尝试。

想在产生任何流量之前先问清楚：

```bash
node scripts/probe-encodings.mjs https://your-gateway.example/v1
```

它发的是一个单 token 请求，而不是真实对话。

**实测：** 3.8 MB 的 body 变成 1.46 MB（38%）。压缩是本插件里要求最低的一件事——只需要对端能解码。

## 预传输

**它做什么：** 为每个对话维护一个**被持有的请求**池，在需要它的请求存在之前就把共享历史放上线路。于是需要它的那一步只追加自己的增量。

**为什么有用。** 一个 `/chat/completions` body 是单份 JSON 文档，任何中转都不会在它完整之前开始推理——所以这并**不会**让模型更早开始。它让中转链**其他**的每请求开销更早结束：token 计数、配额预检、body 日志、WAF 扫描都与已收到的字节成正比，而当上下文达到几百 KB 时，这些开销可能主导整个等待。历史已经在线路上、只需追加增量的请求，就能更早结束这些工作。

**它的前提。** endpoint 必须接受 **chunked** 请求体，因为被持有的成员在增量到来之前无法知道自己的长度。不接受的话，预传输会自己对该 endpoint 关闭，而形状拒绝（`411`/`415`/`501`）会以普通请求重发。

**池的行为。**

- 每个对话持有 `prewarmPoolSize` 个成员（默认 `2`），在错开的时刻打开，并**随着内容变得已知而推进**，因此最终被消费的那个已经在线路上待了好几步，而不是一步。
- 每一步认领那个它的字节**延续得最远**、且头部仍然匹配的成员。匹配越深，剩下要写越少。幸存者被推进，池被补满。
- 本该匹配、但已闲置超过**持有窗口一半、且最长一分钟**的成员**不会被认领**，该行记为 `stale`。它的流正是网关最先放弃的那一条，在已经被放弃的流上补写增量，代价是几秒而不是几毫秒。
- 结束这一轮的步骤（`stop`、`max-tokens`、报错、被打断）而不是以 `tool-calls` 继续时，池**原地不动**——一轮结束通常只是暂停，下一个问题会重复同一份历史。
- `prewarmHoldMs`（默认 `120000`）衡量的是**空闲**，每次推进都重置。成员只有在这么长时间内什么都没发生才会过期。
- 池属于一个**agent**，而不是会话树。子 agent 有自己的 session id，因此有自己的池，子池绝不会和父池混在一起。
- 跨 agent 唯一共享的是「不再对某个 **endpoint** 预传输」这个决定，因为「它是否接受 chunked body」是 endpoint 的属性，而不是提问对话的属性。
- 被持有的请求总是被妥善关闭：被消费的成员写完增量后关闭 body，随后 undici 把 socket 还给 keep-alive 池。被放弃的成员由放弃它的那条路径中止——持有定时器、闲置过久或不匹配、被拒绝的 body、池被释放、或插件卸载。

**怎么读结果。** 走了预传输的行带 **预热** 标记。悬停可以看到预发送字节数、增量、以及成员被持有了多久——最后这个数字就是**真正赢得的提前量**，也是判断加大池子在你的线路上值不值得的诚实依据。

被持有的成员带的是 **chunked** body，面板也会这么显示。

**压缩与预传输可以叠加。** 切分时**同一条**编码流从头贯穿到尾，因此各段解压后仍是一份完整 body，压缩没有被牺牲掉。

**关于字段重排。** 前缀只能是 body 的开头，所以插件想预发送的东西必须靠前。DSH 的适配器把 `messages` 放在第二位，其后是工具 schema 等固定字段——这些都不可能被预发送，于是每个请求都要重新上传一遍。由于 JSON 对象无序，插件把 `messages` 移到末尾，让整个固定部分都能进入前缀。只要无法证明字节安全它就会拒绝这么做：body 必须恰好是 `JSON.stringify` 的输出，这样重新序列化不会动到任何字段自身的字节。按 body 形状匹配的中转会回 `400`/`422`，该请求随即以适配器自己的顺序重发，endpoint 被记住。

## HTTP/2

**先把预期摆正：这不是一个让请求快几倍的开关。** 在上面那次实测里，一个 2.37 MB 的请求，**发送阶段只花了 1.1 ms**，而**等服务端花了 3391 ms**。开了压缩和预传输之后，上传早已不是瓶颈，而任何协议都买不回提供方的思考时间。

它换来的是两件事：

1. **HPACK 头部压缩。** 预传输每一步都会重发**同样的**几 KB 头部；HTTP/2 只发差异。这和预传输是同一个思路，只是对象从 body 换成了头部。
2. **多路复用。** 被持有的池共用一条连接，而不是去争抢若干条，也不再重复握手。

**网关不支持也没关系。** h2 是通过 ALPN 达成的，不提供它的 endpoint 会继续在同一条连接池上走 HTTP/1.1——不报错，也没有需要配置的东西。

**`h2` 标记说的是真话。** 只有**响应确实经 HTTP/2 返回**时，耗时行才会带它。真正协商成 h2 的 endpoint 在设置卡片里什么也不说；被插件放弃的才会被点名。

**明文 h2c 默认关闭。** `allowInsecureH2c: true` 会让 `http://` 的 endpoint 也走 HTTP/2，但那是**没有任何证书**的连接。只在你信任那条链路时才开。

**不提供 HTTP/3**，因为这套技术栈上够不着。见 [INTERNALS.md](./INTERNALS.md#http3)（英文）。

## 耗时

`timing`（默认 `true`）是记录耗时的全局开关；页面只在它开启时渲染该视图。

视图把每次模型调用拆成各个阶段：

```
stream begins ──▶ fetch() ──────▶ body sent ──────▶ first token ──────▶ end
      │             │                │                  │              │
      │          prepare          send            TTFT    │        generation
      │                            └──── server ─────┘   │              │
      └────────────────────────── total ───────────────────────────────┘
```

| 列 | 含义 |
| --- | --- |
| 时间 | 请求发出的时刻，精确到秒。 |
| 提供方 / 模型 | 提供方路由、模型、用途（压缩或会话标题）、标明实际所用算法的 `br`/`gzip` 标记，以及运行中/失败徽标。 |
| 发送 | 请求发出 → **body 完全发送完毕**。 |
| 服务端 | body 发送完毕 → 收到响应头。 |
| 首token | 等到第一个 token 的时长——从请求发出算起；对走了预传输的行，则从成员被认领算起。服务端自己的思考时间在行内提示里。 |
| 生成 | 第一个 token → 流结束。 |
| tok/s | 输出 token 数 ÷ 生成窗口。 |
| 缓存 | 提供方从自己的前缀缓存中服务掉的提示占比。 |
| 请求体 | 压缩过则是 `压缩前 → 压缩后`，否则是单个序列化体积。 |
| 响应体 | 实际**在线路上**收到的字节，外加响应自己声明的 `content-encoding`。显示 `–` 表示完全没有任何 chunk 被归属到该请求，那是接线故障而不是空回复。 |
| 总计 | fetch 调用 → 流结束。 |

悬停表头看含义，悬停行看放不下的部分：准备时间、token 计数、以及响应体积与它的编码。

**关于前缀缓存。** 「缓存」列是提供方自己的口径。前缀复用是**服务端**机制——提供方对提示前缀做哈希并复用已算出的 KV cache——客户端唯一的杠杆是让前缀在各轮之间保持字节稳定，而 DSH 已经做到了。它和预传输是两回事：复用避免重算提示，预传输让字节更早到达。两者互不替代。

测量数据保存在内存里（每会话最近 100 次请求，最近 40 个会话），并**按会话持久化**在部署的存储后端（`~/.dsh/storages`），所以重新打开会话——或重启 DSH——看到的是历史而不是空面板。没有存储后端的 profile 只保留在内存中。

## 直接改文件

设置就是 loader 行的 `config`。设置页会替你写它，而且 Host 会按插件 schema 校验、拒绝不合法的写入——所以**用页面改更安全**。页面也是插件首先读取的位置，因此手改可能被页面覆盖。

```yaml
- insert:
    - id: model-request-accelerator
      name: './plugins/model-request-accelerator/lib/index.js'
      config:
        providers:
          sg:
            enabled: true
            prewarm: true
        encoding: auto
        prewarmHoldMs: 120000
        prewarmPoolSize: 2
        http2: true
        allowInsecureH2c: false
        timing: true
```

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `providers.<name>.enabled` | boolean | `false` | 压缩该提供方的请求。 |
| `providers.<name>.minBytes` | number | `1024` | 低于此体积跳过压缩。 |
| `providers.<name>.prewarm` | boolean | `false` | 对该提供方启用预传输。 |
| `providers.<name>.http2` | boolean | 开了 `prewarm` 则默认开 | 对该提供方提供 HTTP/2。 |
| `providers.<name>.encoding` | `auto` \| `gzip` | 继承 `encoding` | 该提供方的算法。 |
| `encoding` | `auto` \| `gzip` | `auto` | 全局默认。`auto` 优先 brotli、退回 gzip。 |
| `prewarmHoldMs` | number ≥ 1000 | `120000` | 被持有的请求空闲多久后被放弃。 |
| `prewarmPoolSize` | number ≥ 1 | `2` | 每个对话持有多少个请求。 |
| `http2` | boolean | `true` | HTTP/2 的全局总开关。 |
| `allowInsecureH2c` | boolean | `false` | 让 `http://` 的 endpoint 也用 HTTP/2，无证书。 |
| `timing` | boolean | `true` | 记录请求耗时并提供耗时视图。 |

未写出的字段取默认值。某个提供方的 `http2` 默认是**开了预传输就打开**，否则关闭——因为预传输正是 h2 有价值的地方。
